# M8 — Held Item Shader — 0.9.0-dev

## Source and scope

Stray CC0 commit `d91fcd4515b4eda647ee8fd7fa99408f473e5718`. File URLs and SHA-256 values are in `audit/stray-held-item-source-manifest.json`. Procedural shader formulas and defaults come from HeldItemShader/StrayConfig and held_item.vsh/fsh. Solyanka integration is GPL-3.0-only; upstream license retained.

`cosmetic.held_item` adds four real styles: Smoke, Stars, Portal and Galaxy. Tint RGB, fill (.08–.85), intensity (.10–1.50), speed (0–4) and independent first-person left/right switches are exposed. Speed 0 fixes shader time at zero; it does not preserve the current animation phase. Color-picker alpha is ignored: fill controls tint/opacity according to the source effect. Parameters use 8-bit channels, so slider values are quantized by at most 0.5/255 for fill, 0.7/255 for intensity and 2/255 for speed.

This is not Item Name HUD and does not modify the held item's inventory/server data. It does not render a CS2 knife. All masters default off; no new gameplay automation or network requests.

## 26.2 integration

- The old source renderItem/ItemSubmit APIs no longer exist. A ModifyExpressionValue at `ItemFeatureRenderer.prepareMainSubmit(Submit)` changes the per-quad material RenderType only for first-person left/right contexts.
- No injection into foil or outline preparation. Native glint/outline passes remain vanilla. GUI/ground/fixed/head/third-person contexts return the original type.
- Compatible ENTITY/QUADS materials use their existing sprite atlas. Outline types and incompatible vertex layouts return vanilla. This cannot guarantee compatibility with every modded material/blend mode.
- One pipeline combines native ITEM_SNIPPET and GLOBALS_SNIPPET with a sampler bind group: Sampler3 end sky, Sampler4 end portal, Sampler5 settings. Native atlas/lightmap/glint bindings are retained. Built-in Minecraft texture identifiers are references, not redistributed game assets.
- A 2×1 RGBA8 DynamicTexture carries tint/fill and style/intensity/speed. ARGB pixel ordering checked against NativeImage.setPixel's conversion. The shader uses texelFetch, not filtered settings samples.
- Texture creation/upload is on render-thread client ticks and only on config changes. Pipeline metadata is registered before volatile readiness is published. Preparation performs synchronized CPU render-type metadata lookup/creation, not texture allocation/upload; cache capped at 64 atlases, excess falls back to vanilla.
- Disable immediately gates replacement and retains the small texture/cache for reuse. Client shutdown releases the texture and clears cached types. Texture upload failure logs once and falls back to vanilla; toggling retries. Shader compiler/pipeline failures are not guaranteed to be caught by this upload guard.
- GUI uses the existing undimmed embedded instant-save settings, palette, bounded sliders and forward/backward choice buttons. No new screen/save button/preview timer. Module count 36; mixins 38; HUD entries remain 18.

## Explicit parity gaps

- First-person **baked item quads only**. Hands/arms, maps and special model renderers are not replaced.
- No upstream silhouette framebuffer mask/outline or shared entity ESP fill pass; source conditional shader code for those paths is inactive.
- Source first-person fill is intentionally unlit/fullbright with no fog; this is not a physically lit material replacement.
- GUI/third-person items retain vanilla materials; shader source includes inactive upstream branches but they are not advertised as features.
- Native game launch, actual Mixin application, resource reload behavior, special modded materials, native GLSL compilation and Sodium/Iris compatibility need manual validation.

## CS2 Knife audit — still pending

Cs2Knives/Cs2Library/Cs2Viewmodel inspect the user's CS2 installation and VPK/model/skin data. The source also contains a substantial Source 2 decoder, material compositor, skeleton/animation and GPU viewmodel backend. None is integrated in this release. It is not blocked solely on the user providing a path. No Valve models/skins/textures are redistributed and no placeholder vanilla-sword cosmetic is added.

## Validation and manual checklist

The release's `validation/summary.json` records actual clean-build/JUnit counts. `check-held-item-hooks.py` verifies the native method and operation descriptors, single main callsite, compiled handler signature, NativeImage channel conversion, native import resolution, cache and lifecycle guards. These are static checks, not Mixin application.

An optional offline check expands native shader imports and translates to GLSL ES 300 for Chromium WebGL2/SwiftShader compilation/linking. It adds ES precision declarations and an explicit vec2 conversion in vanilla light.glsl, which desktop GLSL permits implicitly. This checks the translated pair only, **not** Minecraft bind groups, native driver shaders, visual output or performance. Evidence includes its translation and false native/GPU verification flags.

In-game acceptance:
1. Start with the master disabled. Confirm vanilla inventory, ground items, glint and third-person view.
2. Enable Held Item Shader; test all four styles on an ordinary block, flat item, enchanted item, shield and offhand item. Verify each hand toggle and switch dominant arm.
3. Test fill/intensity/tint/speed endpoints and speed 0. Reopen GUI/restart to verify persistence. LMB next/RMB previous; no darkening or second settings screen.
4. Check empty hand, maps, heads and other special renderers: no promise of shader fill; they must not crash or blank the scene.
5. F3+T/resource-pack switch, world switch/disconnect/reconnect, disable/re-enable; inspect logs for shader/bind-group errors and repeated allocations.
6. Repeat on vanilla Fabric, then Sodium, then Iris with shaders on/off. Report versions, item/effect and latest.log for failures. No compatibility result is claimed before these tests.
