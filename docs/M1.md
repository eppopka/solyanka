# M1 — historical 0.2.0 implementation

**The YACL GUI described here was replaced in 0.2.1 at the user's request.** Current UI/entrypoint behavior is documented in GUI_PORT.md and README.md. Command/persistence behavior remains relevant.

## Implemented

- Required external YACL 3.9.7+26.2-fabric; optional Mod Menu 20.0.3 adapter.
- General module toggles and independent per-entry enable flags; disabled-by-default rows.
- Dynamic bind/shortcut groups; edit, save, explicitly save-and-add/remove, mouse/keyboard capture, unbind and modifier controls.
- Keyboard vs mouse identity, ordered first-match handling, initial-press-only sends, and consumption of owned repeat/release phases.
- Container/global allow-in-GUI, anvil/chat/settings/text-focus exclusions, connected/focused-window guards.
- Dungeon-class and island filters, backed by a stateless current-tab parser; no stale cross-world cache.
- Exact shortcut tokens, optional leading slash in configured names, appended arguments, command/chat targets and bounded chaining.
- Live alias interception, reserved /solyanka, existing-client-command precedence, cycle and generated-length checks. Long unrelated server commands do not enter alias validation.
- Additive v1 config upgrade; typed decode, stable entry IDs, unknown field retention, validation before activation and transactional disk writes.
- Local error reporting and no fallback server execution when a recognized alias expansion is invalid.

## Intentional differences / remaining gaps

- Unknown class/island context fails closed when a filter is configured; the upstream code permits some unknown-context cases.
- Keyboard and mouse codes are separate; lock modifiers are ignored, but extra active Shift/Ctrl/Alt/Super modifiers prevent an exact modifier match.
- Chat/settings/anvils and focused EditBoxes are always blocked even when GUI execution is requested. Third-party container search widgets that are not EditBox require compatibility testing.
- Aliases apply live through Fabric's outgoing-command event, rather than requiring lobby changes to register a new Brigadier tree. **Alias tab completion/help nodes are pending**, not silently claimed complete.
- Chaining is supported but bounded; cycles/overlong expansions fail locally. Unknown unrelated commands are not constrained by the generated-message limit.
- Current tab parsing covers Area/Dungeon labels and standard `name (Class level)` entries. DEAD/missing or custom-format class labels become unknown; the later shared context module must broaden this with real fixtures.
- All gameplay modules other than these two remain pending. No gameplay automation, pricing, solver or renderer port is included.

## External dependency evidence

YACL and Mod Menu metadata and primary-artifact hashes are recorded in `audit/m1/`. Their exact downloaded API surfaces and the resolved Minecraft/Fabric classes were inspected while implementing adapters. YACL/Mod Menu artifacts are external dependencies, not bundled into the solyanka JAR.

## Validation boundary

Unit tests exercise pure logic and persistence. Static ABI checks match the target input descriptors. Neither proves that mixin application, YACL navigation, signed chat, mod-order compatibility or filter parsing works in an actual game session. Use the in-game checklist before marking feature acceptance complete.
