# M11 — archive visual features (1.1.0)

## Source and scope

Adapted directly from the user-provided `impl.zip`, SHA-256
`94833f79bfeb5a6213ab719f321412848b22ca180ed7e64105ee4d707d39edf3`:

- `impl/visual/AmbientParticles.kt`
- `impl/visual/RotatingItem.kt`
- `impl/visual/MoveHearts.kt`

Exact per-file hashes are retained in `audit/archive-inventory.json` and
`audit/archive-visual-source-manifest.json`. No additional upstream framework or
AetherOSSettings code is included. These are build-tested adaptations, not a claim
that all archive features or upstream option parity are complete.

## Ambient Particles

Eight source styles: End Rod, Fireflies, Cherry Petals, Snowflakes, Souls, Portal,
Witch and Happy Villager. Amount 1–10 spawn attempts per client tick, default 2;
radius 4–32 blocks, default 12. Exact source box distribution and velocities are
retained: X/Z within ±radius, Y from -1.5 to +6.5 relative to player; lateral
velocity ±0.01 and vertical velocity -0.015 to -0.005.

Only calls native `ClientLevel.addParticle` while enabled, in a world with a player
and not paused. No packets, chunk requests, global particle-setting changes or
custom GPU buffers. Vanilla particle culling/settings remain authoritative, so the
visible count may be lower. Already spawned particles expire naturally on disable;
clearing the entire native particle engine would remove other mods' particles.

## Rotating Item

All five source patterns and parameters are adapted: Chaotic, Clockwise,
Counterclockwise, Spin and Wave; speed 5–200, amplitude 5–100 and independent XYZ
offsets -0.5..0.5. X offset mirrors for the left hand. Source rotation order is
translation → X → Y → Z. Wave bob is composed into the translation (equivalent
because it precedes rotations).

Injects at RETURN of native 26.2
`ItemInHandRenderer.applyItemArmTransform(PoseStack, HumanoidArm, float)`.
The installed game bytecode contains five calls in `submitArmWithItem`; empty
hands and map branches bypass them. Native use/equip/swing transforms still run;
some special use branches can bypass this hook too. No third-person, inventory or
world item mutation is performed. The existing Held Item Shader is downstream
and remains independent.

Animation uses monotonic elapsed time, with an epoch reset on enable/disable/world
reset rather than the source's process-relative absolute nano-time phase. Pausing
Minecraft does not freeze this visual phase (same wall-time characteristic as
source); no simulation state is modified.

## Move Hearts

Fabric HUD replacement wraps the previously installed HEALTH_BAR and optionally
ARMOR_BAR elements; it never reimplements or cancels individual health sprites.
Transform is the source baseline formula: translate(savedX - scale * nativeX,
savedY - scale * nativeY), then scale. Default position follows native screen
coordinates; reset returns to that responsive position and scale 1.

Native health flashing, absorption, status-effect sprites and multirow layout are
preserved. Armor, if selected, follows the same transform and keeps its native
relative offset. The HUD editor's 81×9 baseline placeholder is not a complete
multirow/armor bounding box; extra rows/armor can extend above the placeholder.
Only that baseline is clamped to the screen. Extremely small screens or high
scales can still clip native extra rows.

A separate `customPosition` marker distinguishes the valid custom (0,0) position
from default placement. Editing x/y/scale or dragging in `/solyanka gui` sets it.
Editor resolution is passed into first edits, avoiding a snap to a 960×540 default.
RMB editor visibility controls hearts and the armor follower only while this
module is enabled. Disabling the module restores the original elements.

Wrappers are installed after Player Display and No Render. Delegating to the
previous elements preserves those visibility filters; this module never tries to
resurrect hidden health/armor. The editor draws only a placeholder and suppresses
the moved native element there; it does not enable modules or change health.
Every pushed pose is restored in `finally`, including exceptions from delegates.

## UI and lifecycle

Three real modules, all default off. Dedicated embedded settings, immediate atomic
persistence, bounded sliders and forward/backward style choices. No new screen
navigation, background dim, save button or preview button. Existing settings and
`.gitignore` remain intact. HUD editor now has 20 entries; 43 module cards and
41 Mixin classes are registered.

## Validation and manual acceptance

Pure tests cover migration/types/ranges, source particle distribution, all motion
formulas/hand offsets/long-running clocks, native baseline math, resize/tiny-window
bounds, origin handling, editor resolution and persistence. Static ABI checks cover
native transform descriptor and five callsites, compiled injection and delegate,
native particle signature/types and Fabric HUD wrapper API. This is not a launched
Mixin application or visual compatibility test.

Test in game, first with required dependencies, then with Sodium/Iris:

1. Upgrade with only one solyanka JAR. Confirm old settings survive; all three new
   masters start disabled and reopening settings does not darken the world.
2. Cycle all eight particles using LMB and RMB. Change density/radius. Test paused
   single-player, multiplayer, teleport/reconnect, Minimal particles and disable.
3. Test every item mode, both hands/main-arm settings, speed/amplitude/offsets;
   switch maps, empty hands, bow, crossbow, shield, food and spyglass. Pair with
   Held Item Shader and Motion Blur. Disable/world-change should reset the phase.
4. In survival test health damage/heal flash, absorption, poison/wither, multirow
   health and armor. Move/scale in `/solyanka gui`, restart, resize and reset.
   Test custom (0,0), hidden visibility and disabling the master.
5. Enable No Render Health/Armor and SkyBlock Player Display Hide Hearts/Armor in
   turn. Move Hearts must never override hiding; other HUD elements must not move.
6. Compare screenshots/logs with Sodium/Iris and shaders. Native GPU/in-game
   acceptance remains pending; compile/static success is not proof of parity.
