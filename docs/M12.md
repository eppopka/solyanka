## Secret Counter

Module `custom.secret_counter`, default off. Enabling permits one
`/showextrastats` command per detected dungeon completion. While the existing
sidebar/tab context says the player is in a dungeon:

1. Exact Mort map-introduction line resets state at run start.
2. A complete Catacombs completion header schedules one request after 1000 ms.
3. At dispatch, begin a 10000 ms personal-result window. No retries.
4. Accept only an entire `Secrets Found: integer` server-game-message line.
   Strip formatting; grouped digits, zero and Int.MAX_VALUE are supported.
   Reject negatives, percentages, fractions, overflow, player/party prefixes and
   team-total lines. The first accepted result is printed locally once.
5. Optional chat announcement waits 500 ms; Current Chat uses native sendChat,
   Party Chat uses fixed `/pc`. Source message branding becomes `[solyanka]`.
6. Timeout prints one local warning and never announces an estimate.

The source defaults Auto Announce on. This port defaults it **off** to avoid
posting to multiplayer chat before explicit user opt-in. Settings clearly explain
that the master allows the stats command and Auto Announce allows chat output.
No API/HTTP traffic, team-total estimates, outgoing alias expansion or re-sent
stats command. This feature follows server text and can fail closed if messages,
formatting, dungeon context or server command behavior change.

Noamm's broad Floor `.{1,3}` completion pattern is narrowed to Roman I–VII,
numeric 1–7 and Entrance, optional Master Mode/The prefix and whitespace. All
matches are whole-line, not substring triggers. The marker is not a cryptographic
origin guarantee: a server/plugin can emit arbitrary system text. Player CHAT
callbacks are deliberately not registered.

Both Fabric GAME and GAME_CANCELED callbacks are observed, matching the source's
receive-cancelled behavior. The inspected Fabric branch calls one or the other,
not both. Overlays are ignored. State is confined to client message/tick callbacks;
no coroutines, worker threads or delayed scheduled tasks. Monotonic milliseconds
replace wall clock deadlines. Disable, world/reset/disconnect, floor/master change,
leaving dungeon and next-run start cancel pending requests/responses/announcements.
Turning Auto Announce off before dispatch cancels a pending announcement. The
latest selected channel is used if it remains enabled.

There is no new HUD element: the feature reports locally in chat, as the source.
In-game Hypixel run/command acceptance is still pending.

## Always Water

Module `custom.always_water`, default off, with its own embedded explanatory panel.
It means always raining, even beneath roofs. It does **not** place water blocks,
change fluid movement, send weather commands or edit a world heightmap.

Integrates into existing Ambience weather Mixins to avoid competing solyanka
callbacks:

- Client-side Level.getRainLevel RETURN forces 1.0 while enabled.
- WeatherEffectRenderer.extractRenderState precipitation result forces RAIN.
- That method's single getHeight(MOTION_BLOCKING, x, z) result is replaced with a
  synthetic floor only for extraction. Native code clamps all its later uses
  against camera Y / Y±radius before generating columns or querying lighting.
  This removes roof clipping without mutating heightmap data or global getHeight.

Always Water wins over Ambience Clear/Snow for rain/type. Ambience's existing
optional precipitation opacity control still applies; thunder continues to follow
existing Ambience/server behavior. Disabling restores the current server/Ambience
weather immediately on the next extraction. No resources or delayed tasks to
clean up; no global OpenGL calls or framebuffer ownership.

Native precipitation radius, graphics settings, dimensions, light and shader
pipeline behavior are retained. Shader packs may replace or bypass this pass.
Rain splash/audio still follow native behavior; no custom under-roof splash/audio
renderer is added. Do not infer native GPU/Sodium/Iris compatibility from compiling.

## Validation and manual checklist

- Pure tests cover exact start/end markers, duplicate completion, pre-request and
  duplicate responses, time boundaries, negative epochs, malformed/spoof-prefixed
  lines, overflow, timeout/reset, opt-in announcement cancellation and rain policy.
- Static checks cover the native weather target descriptors/callsites, compiled
  expression handlers, client-only rain guard and Fabric callback descriptors and
  dispatch branches. They do not apply Mixins in a running client.
- Existing regressions/translated offline shader checks are repeated. Clean build
  compiles both source sets and validates the access widener.
- 45 registered modules, 41 Mixin classes and 20 HUD editor entries. Eight archive
  feature objects adapted; 14 remain, excluding AetherOSSettings.

In game:
1. Install just one 1.2.0 JAR. Confirm existing settings survive and new masters are
   disabled. Auto Announce must start off and changes must save without a button.
2. Enable Secret Counter in a real run. Completion should cause one stats command
   after one second. Verify the observed personal count, not a team count. Leave
   dungeon/reconnect/disable while waiting; no late message should be sent.
3. Opt into Current/Party announcement separately; confirm exactly one message
   after the local result. Turn it off in the 500 ms delay and verify cancellation.
4. Test stats timeout/server-command rejection, colored/grouped counts, reruns and
   hidden server messages with your chat mods. The feature must not retry/spam.
5. Enable Always Water in clear weather indoors/outdoors, snow/desert biomes and
   different dimensions; no water blocks or server changes should occur. Test
   Ambience Clear/Snow/opacity, then disable and compare restored weather.
6. Repeat weather testing with Sodium/Iris/shaders. Provide module IDs, steps and
   sanitized logs/screenshots for any failures; runtime acceptance is pending.
